# 평가 기록 (2026-10-01)

**확인한 사실**과 **추정**을 구분해 적습니다. 표시가 없는 수치는 이 컴퓨터(WSL2 Ubuntu 20.04, CPU 6코어, 메모리 7.7GB, 쓸 수 있는 GPU 없음)에서 측정한 값입니다.

## 0. 가장 중요한 전제: 사용자 본인 사진으로는 아직 검증하지 않았다

테스트 사진이 제공되지 않았습니다. 그래서 Wikimedia Commons의 **공개 라이선스 제주 사진 12장**(서로 다른 촬영자, 한 사람의 여행이 아님)으로 전체 흐름을 검증했습니다. 여행 외 용도 확인용으로 **반려동물 사진 8장**도 썼습니다. 출처: `samples/*/CREDITS.md`.

이 대체 세트의 한계:
- 촬영 시각(EXIF)이 12장 중 2장에만, 그것도 서로 다른 해에 있습니다. 실제 폰 사진처럼 시각이 다 있는 경우의 **시간순 구성은 합성 이미지 테스트로만** 확인했습니다.
- 같은 사람들이 여러 장에 나오는 사진이 없어, "같은 인물이 장면마다 알아볼 수 있게 유지되는가"는 확인하지 못했습니다.

**미완료:** 본인의 여행 사진 약 10장으로 한 번 만들어 보는 것. 방법은 README의 실행 절차대로 화면에서 올리기만 하면 됩니다.

## 3. 평가 항목별

### 사진과 콘셉트가 반영됐는가 — 부분적으로 그렇다
- **분위기 단어는 확실히 바뀐다 (확인).** 같은 사진으로 A·B·C를 비교하면: 장면 길이 2.37초 / 2.07초 / 2.14초, 전환 겹치기 10회 / 컷 9회+밀기 2회 / 겹치기 8회+어두워졌다 밝아지기 2회, 색감 따뜻함 / 선명 / 차분한 영화톤, 음악 76 / 116 / 84 BPM.
- **사진 내용은 묶음과 순서에 쓰인다 (확인).** A의 순서: 넓은 전경(항공) → 해변 → 길 → 절벽 → 해녀들 → 시장 2장 → 올레 표식 → 고기 → 노을 → 야경. CLIP이 붙인 분류는 12장 중 11장이 사람이 봐도 맞았고(표식 사진 '표지·글자', 고기 '음식', 해녀들 '여러 사람' 등), 절벽 사진 1장은 아래쪽 산책로 때문에 '길'로 분류됐습니다. 또, 거의 같은 노을 사진 두 장 중 덜 선명한 쪽을 뺐습니다(유사도 0.93, 나머지 쌍은 0.79 이하).
- **한계 (확인).** 콘셉트는 단어 규칙으로만 읽습니다. "바다가 주인공인 영상"처럼 특정 대상을 말하면 인물·풍경·음식·동물 4종 외에는 반영하지 못하고, 화면에 "읽어 낸 단서가 없음"으로 표시됩니다. 사진 사이의 관계(같은 사람, 같은 장소의 전후)는 이해하지 못합니다.
- 생성이 필요한 요청("지브리풍", "파도가 치게 움직이게")은 반영한 척하지 않고 "반영하지 못한 요청"으로 표시합니다 (테스트로 확인).

### 장면 순서와 흐름이 자연스러운가 — 대체로 자연스럽지만 사실 순서는 아니다
- 낮 풍경으로 시작해 사람·장소·음식을 거쳐 노을·야경으로 끝나는 흐름은 보기에 자연스럽습니다 (장면별 프레임을 직접 보고 판단).
- 다만 이 세트는 촬영 시각이 없어, 이 순서는 **보기 좋은 배열일 뿐 실제로 일어난 순서가 아닙니다.** 구성안에도 "실제 촬영 순서와 다를 수 있습니다"라고 표시합니다.
- 어색한 점: 올레 표식 사진이 '표지·글자'로 분류되어 풍경 묶음이 아니라 시장 사진들 뒤에 붙었습니다. 반려동물 세트에서는 사람 둘이 개를 산책시키는 사진이 '길' 사진으로 분류되어 첫 장면이 됐습니다.

### 인물·장소가 알아보기 어렵게 변형되지 않았는가 — 원본 편집은 변형이 없다
- 원본 편집 엔진은 가로·세로 같은 배율로 자르고 확대·이동만 합니다. 비율 왜곡 0.000% (모든 장면 계산값).
- 얼굴: 해녀 사진 원본에서 얼굴 8개 검출 → 결과 영상 가운데 프레임에서 7~8개 검출, 모두 화면 안에 온전히 들어옴. 얼굴이 화면을 채우면 잘리는 사진은 자동으로 "넓게 보이기(흐린 배경)"로 바뀝니다.
- 한계: 얼굴이 있으면 얼굴을 우선해 자르기 때문에 다른 주인공이 잘릴 수 있습니다. 반려동물 세트 첫 장면에서 사람 둘은 온전하지만 개가 화면 왼쪽 끝에서 잘렸습니다.
- 입체감 엔진(C)은 깊이에 따라 픽셀을 조금씩 밉니다. 깊이 경계가 뚜렷한 두 장면(전봇대, 절벽)의 시작·끝 프레임을 원본 해상도로 확인했을 때 찢어짐은 보이지 않았습니다. 얼굴 영역은 깊이를 평평하게 만들어 모양이 바뀌지 않게 했습니다. **실시간 재생으로 본 평가는 아닙니다.**

### 움직임과 전환에 어색함·시각 오류가 있는가 — 수치상 오류 없음, 체감은 미확인
- 4개 영상 모두 `scripts/evaluate.py` 점검 통과: 페이드 구간 밖 검은 화면 0, 멈춘 화면 0, 장면 안 프레임 간 변화량의 최대/중앙값 1.16 이하(튀는 프레임 없음), 프레임 수·코덱(H.264 yuv420p)·해상도 일치.
- 겹치기·어두워졌다 밝아지기·밀기 전환 중간 프레임을 직접 확인했습니다. 제목 글자는 원본 해상도에서 선명했습니다.
- **미확인:** 움직임 속도가 보기 편한지, 전환이 너무 잦거나 느린지는 프레임 몇 장으로 판단할 수 없습니다. 실제 재생으로 봐 주셔야 합니다.

### 음악이 장면과 잘 맞는가 — 기술 점검만 완료, 청취 평가는 미완료
- 음원: 앱이 직접 합성 (외부 음원 없음 → 권리 문제 없음). 분위기 5종(잔잔/가벼운/경쾌/웅장/나른).
- 확인: 장면 경계와 박자 차이 최대 0.34ms, 평균 음량 약 -16.8dB, 최대 0.64(클리핑 없음), 스펙트로그램상 박자 구조 정상.
- **미완료:** 저는 소리를 들을 수 없어 음악이 듣기 좋은지, 장면 분위기와 맞는지는 평가하지 못했습니다. 사인파 위주의 단순한 음색이라 상용 음원 수준은 아닐 가능성이 큽니다.

### 다시 만들거나 일부를 바꾸기 쉬운가 — 쉽다 (확인)
- 화면에서 순서 바꾸기(끌기, ▲▼), 빼기·다시 넣기, 장면 길이(박자 단위), 움직임, 화면 맞춤, 전환, 스타일, 색감, 음악, 엔진을 바꾸고 바로 다시 만들 수 있습니다. 스타일을 바꿔도 직접 정한 순서와 제외는 유지됩니다.
- 다시 만드는 데 15~70초. 만든 기록이 남고 이전 결과도 다시 볼 수 있습니다.

다음 단계로 검토할 외부 서비스의 비용은 **추정**입니다.
- 비전 LLM 구성안(예: Claude Opus 5.5, 입력 $4·출력 $20 / 100만 토큰): 사진 10~12장을 긴 변 768px로 보내면 장당 약 500토큰(가로×세로/750 공식 기준)이라 입력 1~2만 토큰, 출력 수천 토큰 → **영상 1편 구성에 약 $0.1~0.3**. 직접 호출해 확인하지 않았습니다.
- image-to-video 생성: 제3자 비교 글 기준 초당 약 $0.04~0.40 (Kling·Veo·Runway·Luma 등, 모드·해상도에 따라 다름). 핵심 장면 3개 × 5초면 **약 $0.6~6**, 처리 시간은 서비스마다 장면당 수십 초~수 분. 가격표를 직접 검증하지 않았습니다.

## 6. 다음에 개선할 가장 중요한 3가지

1. **구성안을 비전 LLM에 맡기기.** 지금 가장 약한 곳은 콘셉트 이해와 사진 사이 관계 파악입니다(단어 규칙 + 분류). LLM이 사진을 보고 장면 선택·순서·강조·장면별 이유를 JSON으로 내고, 현재의 렌더러·편집 화면은 그대로 씁니다. 사진이 외부로 나가므로 사용자 동의와 API 키가 필요합니다 (추정 비용 영상당 $0.1~0.3).
2. **핵심 장면 몇 개에만 실제 움직임 생성(image-to-video) 붙여 비교하기.** 엔진 자리와 mp4 장면 교체 경로는 준비돼 있습니다. 같은 사진으로 "원본 편집 / 입체감 / 생성" 세 가지를 나란히 만들어, 생성의 추가 가치가 비용(영상당 약 $0.6~6)과 인물 변형 위험을 넘는지 판단해야 합니다.
3. **음악을 실제 음원으로.** 권리가 확인된 음원 목록 또는 사용자가 넣는 음원에 박자 검출을 붙여 컷을 맞추고, 사람이 직접 들어 보는 평가를 합니다. 합성 음악은 권리 문제는 없지만 품질 확인이 안 된 가장 큰 공백입니다.

그 전에 할 일: 본인 여행 사진으로 한 번 만들어 보고, 특히 **촬영 시각 순 구성**이 자연스러운지 확인.
